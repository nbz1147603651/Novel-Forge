# 配音模块(Voice Studio)优化方案

## 核心目标
1. **修复后端关键断点** — 让 TTS 的 LLM 智能增强路径真正生效
2. **修复前端交互逻辑断点** — 音色下拉、自动匹配、偏移参数应用等
3. **UI 精美化** — 复用现有 design token 体系,MetricCard/EmptyState/StepIndicatorRow,让信息层次更清晰、交互更符合直觉

## 一、后端修复(2 处,小而关键)

### 1.1 注册 TTS 提示词模板(最高优先级)
**文件**:`novel_forge/prompts/registry.py` 第 47-208 行 `_TASK_TEMPLATE_MAP`
- 在 `HUMANIZE_PARAGRAPH_REWRITE` 之后(第 207 行后)补两行:
```python
# TTS tasks (tts/)
TaskType.TTS_BUILD_NARRATOR_PROFILE: "tts/build_narrator_profile.j2",
TaskType.TTS_GENERATE_DUBBING_SCRIPT: "tts/generate_dubbing_script.j2",
```
- 模板文件已存在(`prompts/prompts/tts/*.j2` 和 packs/zh|en 副本),仅缺注册映射。修复后 `build_narrator_profile_step` 和 `generate_script_step` 的 LLM 路径不再 KeyError 被吞,旁白画像/配音脚本智能生成真正生效。

### 1.2 同步检查 prompt INDEX 文档
- `novel_forge/prompts/prompts/INDEX.md`(en 根索引)目前未列出 tts 模板,补上两条目(对齐 zh INDEX 已有的条目)。

## 二、前端交互逻辑修复(3 处)

### 2.1 音色下拉框接通 — 替换空 `pass` stub
**现状**:`_on_voice_combo_changed` 是空 `pass`(page.py:1157),下拉项永远是"加载中...",音色选择实际无法工作。
**修复**:
- 选中角色时,调用 `adapter.list_system_voices(provider, language)` 异步加载该 provider 的系统音色列表填充下拉(用 PreviewVoiceWorker 同款 registry 获取 adapter 的方式,或新增轻量 `ListVoicesWorker`)。
- 选定音色后,更新当前角色 `VoiceCastEntry.voice_id` 并持久化 `voice_team.json`。
- 保持 `_voice_combo` 的 `currentIndexChanged` 信号连接,但用 `blockSignals` 防止重建列表时的递归触发。

### 2.2 自动匹配改用后端真实逻辑 — 替换硬编码
**现状**:`_on_auto_match` 把所有未分配角色硬编码为 `male-shaonian-xinchen`(page.py:1193-1210)。
**修复**:
- 改为调用 `BuildVoiceTeamStep._match_system_voice()` 的逻辑(提取为可复用函数),按 gender/age/role/voice_description 做真实匹配(后端 build_voice_team_step.py:193-251 已有完整实现)。
- 若 `voice_team.json` 已存在但部分 entry 缺 `voice_id`,只补这些 entry,不重建整队。完成后持久化并刷新列表。
- 为避免在 UI 线程阻塞,用 worker 包装(新建 `AutoMatchWorker` 调用一个不涉及网络克隆的纯匹配函数)。

### 2.3 角色音色偏移参数应用
**现状**:语速/音调/音量三个滑块拖动只更新 label 文本,从不写回 entry,也不持久化。
**修复**:
- 选中角色且有 entry 时,滑块初始值从 `entry.speed_offset/pitch_offset/vol_offset` 读取。
- 增加"应用参数"按钮(或滑块 release 即时写回),更新 `entry` 对应字段并持久化 `voice_team.json`。
- 用 frozen dataclass 的 `dataclasses.replace` 模式更新 entry(voice team entries 是 list,需替换 list 中的对应项)。

## 三、UI 精美化(最大块,复用现有 token 体系)

### 3.1 配音团队 Tab 重构
- **左列角色列表**:角色项加音色状态色点(✓ ready / ⏳ pending / ⚠ expired),用 `Badge` 小胶囊标 provider;选中项高亮。
- **右列顶部加 4 个 MetricCard(compact)**:角色总数 / 已配音色 / 克隆中 / 过期 — 仿 dashboard 的 `add_card_grid`。
- **音色详情区**:把纯 `QTextEdit` 纯文本改为结构化展示(角色名大标题 + 定位/性别/年龄 Badge 行 + 音色信息 + 声纹描述),用 `SectionHeading` + `Badge` 组合。
- **无角色时用 `EmptyState`** 替代 `QTextEdit.setPlainText("未找到角色数据...")`(page.py:1153)。
- **音色克隆/AI设计/试听**按钮分组:克隆和设计归入"音色来源"组,试听单独突出(primary)。

### 3.2 配音脚本 Tab 精美化
- **段落渲染增强**:当前只显示 `[角色名] 文本`。利用 `DubbingSegment` 已有的丰富字段:
  - 情绪标签:段首显示 `emotion` 色彩点 + 文字(15 种 EmotionTag 各一色),`tone_hint` 作为副标签。
  - 重音词:`stress_words` 在文本中高亮(已有 word_highlight 机制可复用)。
  - 副语言:`paralinguistic_tags` 用小图标标注(如 ⏸ pause / 😂 laugh)。
  - 场景转换:`transition` 段用分隔线 + 标签(如"━━ 三天后 ━━")。
- **角色头像条**:加 provider 色边、未分配音色时灰显;选中态用 accent.primary。
- **段落状态色**:统一到 design token(`status.success/danger/warning/info`),替代硬编码 `#4CAF50/#F44336`。
- **顶部加段落数 MetricCard**:"旁白 N 段 / 对白 N 段 / 音效 N 段 / 总时长"。

### 3.3 音频试听 Tab 精美化
- **顶部进度区**:把单一 `progress_badge` 升级为 `StepIndicatorRow`(4 步:构建团队→脚本→合成→装配),接 `step_progress` signal 实时更新;`FullTTSPipelineWorker` 时尤其直观。
- **播放器区**:DubbingPlayerWidget 已较完善,保持;优化其右侧实时脚本/字幕的卡片间距与标题对齐。
- **导出区**:三个导出按钮用 `Surface("card")` 包裹,加图标 + 说明文字;导出成功后 badge 显示路径并支持"打开文件夹"。
- **无音频时 EmptyState**:"尚未合成音频,请选择章节后点击「合成音频」"。

### 3.4 TTS 设置 Tab 微调
- API 密钥行用 `make_line_setting(secret=True)` 替代手写 `QLineEdit+setEchoMode`(已有"显示/隐藏"切换)。
- 保存设置后,新增"已保存"短暂 toast/badge 反馈(已有,但增强可见性)。
- 各 provider 密钥区按 provider 折叠分组(MiniMax 组 / DashScope 组 / 腾讯云组 / 本地组),而非全平铺,更清晰。

### 3.5 底部状态栏增强
- 当前仅一个 Badge + 取消按钮。增加:当前步骤名(接 step_progress)、进度百分比(合成时)、耗时计时(可选)。
- 状态色严格按 token:运行中 `warning` / 成功 `success` / 失败 `danger` / 取消 `muted` / 就绪 `default`。

## 实施顺序与风险控制
1. **先后端(1.1, 1.2)** — 2 行注册 + INDEX 文档,零风险,立即生效。
2. **前端逻辑修复(2.1-2.3)** — 改动集中在 page.py,需保持 worker 信号契约不变。
3. **UI 精美化(3.1-3.5)** — 重构 page.py 的 `_create_*_tab` 和 `_render_*` 方法,逐 tab 推进,每改完一个 tab 跑一次 `QT_QPA_PLATFORM=offscreen pytest tests/desktop/` 确保不破坏页面快照测试。
4. **QSS 补充(四)** — 与 3 并行,新增 objectName 不影响现有。
5. **清理(五)** — 最后,低风险。
