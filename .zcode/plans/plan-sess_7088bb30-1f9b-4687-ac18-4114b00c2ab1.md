# 修复 StoryBible world_rule_book 校验崩溃（12 个 extra_forbidden 错误）- 修正版

## 根因总结

提交 `0eb9a23a` 引入 `WorldRuleBook` schema，但缺乏 before-validator 容错。从失败项目 checkpoint 实测，LLM 把规则字段分布在**连续三层**：

- **外层 `world_rules`**：平铺了第 3 条规则（WB003）的 `rule_id`/`content`/`category`...
- **`world_rule_book` 顶层**：含 `rules`（14 条字符串，旧格式）+ 平铺第 2 条规则（WB002）的字段
- **`world_rule_book.world_rule_book` 内层**：含第 1 条规则（WB001），字段最完整（`rule_id`/`content`/`category=ability_tech`/`severity=hard`...）

`WorldRuleBook` 继承 `extra="forbid"` 且无清洗器，平铺字段触发 12 个 `extra_forbidden`，`StoryBible.model_validate` 崩溃，初始化失败。

另外，`_assign_ids_and_hash`（after-validator）只按 `rule_id` 去重，**不按 `content` 去重**，因此回收的规则若与字符串 `rules` 摘要内容重复，会留下重复规则。

## 修复方案（4 层，已按 review 修正）

### 层 1：`WorldRuleBook` before-validator — 递归提取每层规则 + 显式 content 去重

**文件**：`novel_forge/core/schemas/world_rules.py`

在 `WorldRuleBook` 新增 `@model_validator(mode="before")` 方法 `_extract_rules_from_nested_layers`。核心逻辑：

1. **递归遍历每一层 `world_rule_book`**：检测 dict 中 `world_rule_book` 键，若其值是 dict，**递归处理**该内层（而非深合并覆盖）。每一层都独立提取候选规则，避免 WB001/WB002 字段竞争丢失。

2. **每层单独提取候选 `WorldRuleSpec`**：检测 `WorldRuleSpec` 的 11 个字段（`rule_id`/`content`/`category`/`severity`/`always_on`/`applicability_tags`/`trigger_conditions`/`allowed_behavior`/`forbidden_behavior`/`cost_or_consequence`/`exceptions`）是否出现在当前层。若有 `content`（非空），把这些字段组装成一条候选规则 dict，追加到候选列表。

3. **统一候选项**：把原始 `rules`（经现有 `_coerce_legacy_rules` 逻辑转成的对象列表）+ 各层回收的候选规则，统一成 `list[dict]`。

4. **显式 content 去重**：按规范化后的 `content`（去空白）去重。当字符串旧规则与回收的对象规则 content 相同/包含时，**优先保留字段更完整的对象规则**（统计非空字段数，取较多者）。这补足了 after-validator 不做 content 去重的缺陷。

5. 清理顶层中所有 `WorldRuleSpec` 字段和嵌套 `world_rule_book` 键，只保留 `version`/`rules`/`source_hash`/`description` 等合法字段。

实现要点：
- 复用现有 `_stable_rule_id`、`coerce_text_list` 工具
- 非 dict 输入直接返回
- `_coerce_legacy_rules` field_validator 和 `_assign_ids_and_hash` after-validator 保留不变
- 详细 docstring 说明三层畸形模式和提取策略

### 层 2：prompt 契约修正（无 JSON 示例，仅加两句约束）

**文件**（仅 stable pack，不改 legacy）：
- `novel_forge/prompts/packs/zh/templates/initialization/init_story_world_rules.j2`
- `novel_forge/prompts/packs/en/templates/initialization/init_story_world_rules.j2`

按 `prompts/AGENTS.md` 第 129 行约束，**不添加 JSON 示例块**。仅修改「字段内容约束」段，加入两句：
- zh：`world_rule_book.rules 是对象数组，不是字符串数组。` + `每个规则的全部字段只能位于 rules 的数组元素内；不得平铺在 world_rule_book 或 world_rules 顶层。`
- en：对应英文翻译

同时把第 60 行（zh）/第 61 行（en）的「每条 `world_rule_book.rules` 必须包含」改为「`world_rule_book.rules` 的每个对象必须包含」，消除「rules 是字符串数组」的歧义。

### 层 3：回归测试（三层嵌套 + content 去重 + 端到端）

**文件**：`tests/unit/test_world_rule_governance.py`（追加）

1. `test_world_rule_book_extracts_rules_from_three_nested_layers`：用与失败项目相同的三层畸形结构（WB001 在内层、WB002 在 book 顶层平铺、WB003 在外层 world_rules 平铺、rules 为 14 条字符串），断言 **WB001、WB002、WB003 都被保留**（按 rule_id 或 content 前缀断言），而不只是「不抛异常」。

2. `test_world_rule_book_deduplicates_by_content_preferring_full_objects`：构造一条字符串规则与一条回收对象规则 content 相同，断言去重后只保留对象规则（字段更完整），验证 content 去重 + 优先级逻辑。

3. `test_story_bible_tolerates_malformed_world_rules_fragment`：**端到端**测试，用原始 `world_rules` fragment dict，经 `_merge_story_fragment`（从 `init_split_artifacts` 导入）合并进 payload，再 `StoryBible.model_validate`，断言不崩溃且 `world_rule_book.rules` 非空。这回归用户报告的实际崩溃路径。

4. prompt 覆盖检查：断言 zh 和 en 两个模板都包含新增的两句约束文本（用 `PromptRegistry` 渲染或直接读文件）。

### 层 4：数据修复 — 删除青瓦梦匙脏 checkpoint

**文件**：`data/青瓦梦匙/initialization/fragments/story_bible/story_bible_independent_fragments.checkpoint.json`

删除此 checkpoint（含畸形数据）。注意：这会让同一 checkpoint 中的 `world` 与 `themes` 两个分片都重新生成。`story_core.checkpoint.json` 保留（依赖未脏）。`story_bible_continuity.checkpoint.json` 在新 world 输出后因签名变化不会复用，无需手动清理。`story_bible.json` 未落盘，无需清理。

## 不修改的部分

- `VersionedSchema.model_config = {"extra": "forbid"}`：保持全局严格性
- `_merge_story_fragment`：只是搬运工，清洗职责在 schema 层
- `coerce_world_rule_book`：在 `model_validate` 之后运行，schema 清洗后自然正常
- `_coerce_legacy_rules` / `_assign_ids_and_hash`：保留原有职责
