# UI 主题管理统一化修复 — 收尾与 QSS 模板迁移

## 背景与发现

本次审查发现两个问题：

1. **真实 Bug（必须修）**：`outline_editor.py` 的 f-string 拼接中，4 处普通字符串行（无 `f"` 前缀）含 `}}` 未折叠，导致 Qt 报 `Could not parse stylesheet` 警告（实测 7 条），并使 `test_outline_mode_tabs_center_label_content` 在完整套件中失败。受影响行：223、316、526、540。

2. **总结夸大的"主题切换自动跟随"不成立**：7 个文件都在 setup-time 调 `resolve_qcolor()` 把颜色烤进一次性 `setStyleSheet()`，且均未实现 `refresh_theme_colors()`。主题切换机制（`runtime.py::_refresh_theme_aware_widgets`）只刷新 paint-time 调用和实现了 `refresh_theme_colors()` 的 widget——这些 widget 两者都不沾，切换主题后颜色冻结（行为与改前一致）。

**已确认的架构方向**（用户选择）：修 Bug + 把内联样式表迁移到 `theme/qss/part_*.py` 全局 QSS 模板（用 `{{token.name}}` 占位符 + `rgba({{token}}, alpha)` 语法），由 `get_stylesheet()` 按主题统一解析，从而真正实现主题跟随。

**范围**（用户确认）：仅迁移本次改过的、使用 `resolve_qcolor` 的调用。`outline_editor.py` 里另外 20+ 处硬编码 `#rrggbb`（本次未动）保持原样。

## 关键架构事实

- QSS 模板规则放在 `novel_forge/desktop/theme/qss/part_XX_*.py` 的 `CONTENT` 字符串里，经 `components.py` → `_raw_combined_qss()` → `get_stylesheet()` 流转，`{{token}}` 占位符按当前主题解析。**模板规则自动跟随主题切换**（`apply_desktop_theme` 重设 `app.setStyleSheet()` 即重解析全部模板）。
- 已存在的属性选择器模式：widget 设 `setProperty("severity", "critical")` + `setObjectName("memorySeverityDot")`，模板写 `QLabel#memorySeverityDot[severity="critical"] { background: {{status.danger.critical}}; }`，运行时改属性后调 `style().unpolish(w); style().polish(w)` 刷新。
- **重要发现**：`part_10_memory.py` 已有 `memorySeverityDot`/`memorySeverityLabel`（含 `[severity=critical/high/medium/low]`）和 `memoryReviewScoreValue`（含 `[grade=pass/warn/fail]`）的模板规则。`unified.py` 的修改在重复造这些规则——正确做法是直接用已有 objectName + property，删除内联 `setStyleSheet`。
- `rgba({{token}}, 0.10)` 语法可用（`__init__.py::_rgba_replacer` 把 hex 转 RGB 后拼 `rgba(r,g,b,alpha)`）。
- `_get_viewer_default_qss()` 是给 `QTextDocument` 用的 HTML CSS，**不走** `get_stylesheet()`，`{{token}}` 在此不生效——必须保持动态（保留 `resolve_qcolor`），但需加 `refresh_theme_colors` 重建。

## 风险与缓解

- **objectName 冲突**：迁移前已 grep 确认新 objectName 不与现有模板规则冲突（`docSplitter` 已有，需合并而非新建）。
- **共享 objectName**（`formFieldHint`、`memoryMeta`）：改用唯一 objectName 或属性选择器，不写 blanket 规则。
- **属性选择器不刷新**：运行时改属性后必须 `unpolish/polish`；本次迁移的动态点（score grade、step-flow state）需在 `update_reading_power`/`_update_step_flow` 里加。
- **QSS 顺序敏感**：新 `part_15_standalone.py` 放在拼接末尾，确保不覆盖既有规则；`docSplitter` 扩展在原位置（part_02）。
- **测试回归**：`test_outline_editor_layout.py` 断言了 `background: #fffaf3;` 等硬编码值（行 134-135），迁移后这些值变成 `{{bg.surface}}` 解析结果（仍是 `#fffaf3`），需确认测试断言与解析后值一致；若测试断言的是 `setStyleSheet()` 返回的字符串，迁移后该调用被删，需更新测试改为检查模板规则存在或 widget 实际渲染颜色。
