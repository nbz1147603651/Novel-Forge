**Protect subjective design intent:** explicit author instructions, human edits and locks outrank AI preferences. Scores, reading-power suggestions and AI-flavor reduction do not authorize changing an ending, core character fate, world rules, voice, intentional pacing/repetition, total scope or archived prose. **Frontend/backend coherence:** use one effective backend policy for allowed actions, scope, versions, stop state and reasons. Update Python contracts/API/job/workspace behavior, shared TS contracts and NIMO consumers together; include PySide/CLI where affected. Preserve explicitly saved old choices; never silently elevate autonomy during migration.

**Avoid over-optimization:** fix an evidenced problem with the smallest coherent change. Reuse the existing control plane, autorun, finalization manifest, intent projections and planning revisions. Do not add a second scheduler/canon, speculative parallelism, fact truncation, endless quality loops or blanket UI redesign. **Pipeline Flows:**

> This is a responsibility-level overview. See [the current workflow](docs/novel-workflow-current.md) for dependencies, flags, manual decisions, recovery and differences between direct and checkpoint/autorun entry points.

Short story: `Spec + research → Blueprint/ElementSelect → Beats + StyleProfile (parallel) → Execution Plan/kernel → Draft → [bounded adaptive revision OR candidate-first Edit/completeness/full-evaluation/quality repair] → Creative Analysis → final text/reports/state/memory handoff`. Candidate-first is the default; the legacy execute-first verifier is a feature-flag fallback for one release cycle. Export is a separate operation.

Long init: `request fingerprint + explicit intent → Spec/research → StoryBible + BlueprintElementSelect (parallel) → CharacterBible → knowledge boundaries + StyleProfile + EntityGraph → CreativeDirectorPacket (optional 2+1 exploration) → Blueprint/validation/candidate repair → Batched Outline + Chapter Design → Narrative/Chapter Contracts + isolated coherence candidate + original-postcondition verification → kernel/entity/source readiness + memory`. Configured characters/concept/blueprint/outline/contracts checkpoints can interrupt this flow. Full/progressive controls coverage, not total book size or author authority. Initialization candidates are not authority: approved foundations still require the existing versioned proposal path.

Long chapter (6-phase):
1. **Planning**: `StatePacket → Context Compress → ReadingPowerWindowManager init → Bridge → Plan(absorbs Bridge opening anchors) → Input Integrity Check`
2. **Generate**: `prepare_generate_context → Draft (per-scene prose, 20-field scene_intent subset, no voices) → ChapterRepair (optional) → Wave (single-pass scene weaving, full plan + cross_scene_intent + full voices)`
3. **Review**: `Opening Guard Patch → Quality Checks (alignment + continuity + chapter-repair audit, with causal precompute) → Continuity Repair Loop → Alignment Repair (if needed) → Dedup + Pronoun + Self-repetition (parallel) → Mechanical Pronoun Fix → Guard Constraint Compliance → Causal Repair Loop (cross-dimension coordination) → Reading Power Repair Loop → Extract + Eval (parallel) → Guidance Contract Audit`
4. **Polish**: Optional/threshold-driven post-repair polish; semantic changes require refreshed extraction, evaluation and audits. A configured score trigger is not permission to override author intent.
5. **Humanize**: `AI-flavor cleanup + repair (only when `humanize_enabled=True`)`
6. **Finalize**: Terminal text refinement/verification follows configured branches; final gates, reports and state extraction must match the final text hash before completed handoff. Persist text/reports and required state using the finalization manifest; auxiliary memory and publication projection have separate recovery. MacroGuard and future planning are not interchangeable with archive completion.

**Generate-stage split (DRAFT vs WAVE):**
- `stages/draft.py::prepare_generate_context` builds the shared `GenerateContext` (kernel composer, memory hints, canon context, focus ids, etc.).
- `stages/draft.py::generate_draft(ctx)` runs `DraftStep` and the optional `ChapterRepairStep`. **DRAFT only sees 20 fields of `scene_intent` (no voices, no cross-scene intent)** so each model focuses on what it actually needs.
- `stages/wave.py::apply_wave(ctx, draft_text)` runs `WaveStep` **exactly once** (no multi-round edit loop). **WAVE sees the full 35-field `scene_intent`, full editorial contract (incl. `character_voices`), and `cross_scene_intent` (cross_scene_references + pacing_curve)** for cross-scene consistency.
- The orchestrator `chapter_flow.generate_chapter_prose()` chains them and returns a `GenerateArtifacts` dataclass (`current_text`, `performed_edits=1`, `wave_meta`).
- WAVE post-conditions (5 checks: cross-ref hits ≥ 80%, pacing_curve length, scene anchors, word count ±30%, POV consistency) **never raise**; failures are recorded as warnings on `WaveOutput.warnings` and surfaced to the Review stage.

**Bridge/Plan source ownership:** Bridge remains a lineage/audit artifact. `pipeline/long/stages/planning.py::absorb_bridge_into_plan()` copies executable opening anchors into `ChapterPlan.opening_bridge`; DRAFT and DRAFT_SCENE must read that Plan field, not `stage_cards.bridge`.

**Source artifact projection boundary:** Runtime stages do not receive full raw `project_spec`, `character_system`, `entity_graph`, or `blueprint` payloads. `ChapterSourceSlice` exposes bounded projections (`chapter_contract`, `relevant_entities`, `story_foundation`, `style_voice`, `creative_direction`, etc.) so chapter stages cannot bypass contracts or leak future blueprint payoff.

Key architectural notes:
- **Checkpoint/resume**: `ReviewProgressState` persists after each stage (draft_done/quality_done/repair_done/canon_done) for crash recovery. `draft_done` is set after the WAVE pass completes (not after DRAFT alone) so resume skips both DRAFT and WAVE.
- **Cross-dimension coordination**: Causal repair intensity reduced if continuity was exhausted; skipped entirely if continuity < hard floor; causal repair that drops continuity > 1.5 points triggers revert to pre-causal text
- **Global repair budget**: `total_rounds_cap=5` across all repair dimensions (configurable via `long_total_repair_rounds_cap`)
- **Emergency checkpoint**: On `CancelledError`, latest draft is recovered from disk and saved as checkpoint

## Critical Conventions

### Frozen Dataclasses — `dataclasses.replace()` ONLY

```python
# ❌ Direct assignment → FrozenInstanceError
state.field = new_value

# ✅ Always use replace
import dataclasses
state = dataclasses.replace(state, field=new_value)
```

Affects `PendingChapterReviewState`, `TaskFormatContract`, `RuntimeConfigSnapshot`, and all `@dataclass(frozen=True)` types. Never write directly.

### PipelineStep Pattern

All steps inherit `PipelineStep[InputT, OutputT]` (generic ABC). Subclasses implement `async def _execute(self, input: InputT) -> OutputT`. The framework (`run()`) auto-adds: retry (2x), token escalation, tracing, logging. Don't reimplement these.

### Repair Module Architecture

The active long-chapter repair path is domain-specific orchestration in:
- `pipeline/long/stages/continuity_repair.py::run_continuity_repair_loop`
- `pipeline/long/stages/causal_repair.py::run_causal_repair_loop`
- `pipeline/long/stages/quality_checks.py::run_reading_power_repair_loop`

Step-level repair logic lives in `pipeline/steps/continuity_repair_step.py`, `pipeline/steps/causal_repair_step.py`, and `pipeline/steps/reading_power_repair_step.py`. Shared patch/fulltext guards live under `pipeline/steps/repair/` (`base.py`, `patch_bridge.py`, `word_guard.py`, `text_utils.py`, `forbidden_checker.py`).

`pipeline/long/repair_safety.py` is the production safety kernel for all repair dimensions: it classifies gateway/internal errors, emits structured events, and returns the last validated text/report rollback anchor. Active loops and the generic runner should both use this policy instead of hand-building failure events. Use its typed `RepairDimension`, `RepairFailureKind`, `RepairFailureOperation`, and `RepairFallbackAction` values for shared semantics; custom domain action strings are allowed only when they describe a real domain-specific fallback.

`pipeline/repair_orchestration/loop_runner.py` is the generic repair loop core (`_RepairRoundKernel`). The active chapter path is: `chapter_flow_review.py` → `run_*_repair_v2` (`repair_orchestration/domains/{continuity,causal,reading_power}.py`) → `_execute_*_repair_loop` (`long/stages/*_repair.py`) → `ContinuityRepairRunner` / `CausalRepairRunner` / `ReadingPowerRepairRunner` (kernel subclasses). The former `pipeline/long/repair_loop_runner.py` compat shim was removed after the v2 migration.

Repair fallback rules:
- Use `RepairFailurePolicy` for repair, recheck, validation, and post-repair regression/check failures when a safe fallback exists.
- Preserve or roll back to the last validated text when repair or recheck fails; never keep unverified repaired text after a failed post-repair validation.
- Emit structured step events with `error_kind`, `error_type`, and `action` so Desktop and logs show the reason and chosen fallback.
- Leave hard gates in `finalize.py` responsible for blocking/replanning chapters with residual high-severity issues.

## PySide6 Fallback Gotchas

- **Event loop**: Each worker runs its own `asyncio.run()` — never share the main thread's loop
- **Thread safety**: All UI updates must go through Qt signals/slots, never direct Widget access from workers
- **Shutdown**: Every page's `shutdown()` must disconnect worker signals and stop timers
- **CI**: Tests need `QT_QPA_PLATFORM=offscreen` env var
- Desktop has 54 page modules across `pages/`; check `novel_forge/desktop/pages/AGENTS.md` before touching page state or worker wiring.
- `sleep_inhibitor.py` prevents macOS/Windows/Linux system sleep during long generation runs
- `jobs.py` manages background task queue with structured error summaries and step progress tracking

## Testing

- `asyncio_mode = "auto"` — no `@pytest.mark.asyncio` needed, no manual loop management
- `tests/conftest.py` has shared fixtures (mock_adapter, router, builder, settings, tmp_storage, sample_spec, sample_canon_state, sample_canon_delta); check before adding new ones
- Broken tests are expected to fail — never delete tests to make CI pass
- Test-file counts (total + per suite) are machine-generated in the facts block at the top of this file
- Parallel testing: `pytest -n auto` via pytest-xdist
- Timeout: 300s default with `pytest-timeout`, method=thread
- Environment: `QT_QPA_PLATFORM=offscreen` and `NOVEL_FORGE_MEMORY_USE_MOCK_EMBEDDINGS=true` (set in `pyproject.toml` `[tool.pytest.ini_options].env`)
- Markers: `unit`, `integration`, `regression`, `timeout(seconds)` (honored when `pytest-timeout` installed)
- **CI matrix** (`.github/workflows/ci.yml`): NIMO TypeScript/Vitest/build checks are the primary UI gate. Unit + integration run on ubuntu/windows/macos-latest with the CI Python version declared in the facts block. PySide fallback compatibility/reference jobs remain explicit; Ubuntu needs `libegl1 libgles2 libgl1` for them.
- **CI lint job** runs `ruff` plus `check_mypy_baseline.py` (strict-mypy debt regression gate), then `lint_prompt_layers.py`, `audit_prompt_format_layers.py --all`, `audit_prompt_packs.py`, `generate_prompt_index.py --check`, `verify_templates.py`, `verify_format_contracts.py`, `verify_control_plane_constraints.py --check`, `verify_design_tokens.py --check`, `check_agents_md_drift.py`, `check_call_site_sync.py`, `lint-imports` — all required to pass. `typing/mypy_baseline.json` is a line-number-independent debt inventory; refresh it only in an explicit typing-debt commit.

## Core & Contract Boundaries

Two high-cochange chains are registered as explicit boundaries (evidence: 500-commit co-change analysis, confidence low):

- **Contract chain**: `packages/engine-contracts` ↔ `clients/nimo-desktop` (plus `tools/ui-parity` as the parity harness). Engine contract changes MUST trigger every consumer layer: Python API route tests and the nimo desktop type-check + vitest suite.
- **Service chain**: `novel_forge/desktop` ↔ `novel_forge/tts` ↔ `novel_forge/workspace` (cross-layer calls between the PySide UI, TTS service, and workspace execution facade).

Mechanical enforcement: `scripts/check_contract_consumers.py` (CI job `contract-consumers`) detects boundary changes in the current commit and runs the consumer validation set; when no boundary path changed it exits fast without running anything. Directional guidance stays here; the script is the source of truth for the exact command set.

When the dual-UI convergence period ends, evaluate single-stack deletion (PySide or nimo) and remove the stale boundary half; do not keep two parallel implementations indefinitely.

## When Things Go Wrong

1. **ConsistencyViolationError** → automatic chapter replan up to 2 times
2. **ModelGatewayError** with `is_transient=True` → automatic retry with token escalation
3. Missing JSON keys in LLM output + `enforce_required_keys=True` → automatic retry
4. No real provider configured → `MockAdapter` fallback (returns plausible mock data)
5. `NOVEL_FORGE_API_CALL_TIMEOUT_S` → increase for slow models or complex tasks
6. Desktop worker crashes → check QT_QPA_PLATFORM=offscreen in CI, ensure asyncio.run() per worker
7. RuntimeServices stale config → call `reload_runtime_dependencies()` to rebuild without restart
