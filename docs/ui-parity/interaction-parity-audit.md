## 本轮补齐：火候任务级路由

源端 `settings/page.py` 的路由不是简单的“任务 → 模型”表，而是：流程大组 → 子流程 →
单任务覆盖。每行有任务说明、主模型、与任务绑定的思考/多轮开关、按候选模型分别配置的
备用能力、可排序回退队列，以及只对适用任务显示的 `0.00–2.00` 温度。

React 的 `model-routing-session.ts` 现在将此建模为纯本地草稿：

```text
默认模型 ──────────> 仅在任务未指定主路由时继承；不暗中改写任务级覆盖
流程大组批量应用 ──> 同时覆盖主模型 / 思考 / 多轮 / 回退顺序
子流程批量应用 ──> 同上，但仅覆盖其任务集合
单任务温度 ──> 始终保留，不受批量操作重置
备用候选 ──> 依优先级排序；可调用候选的前 3 个生效；能力按候选自身判断
```

路由工作台在页面内按需装载；打开时会收起通用运行总览和连通性卡片，避免在 1440×900
挤占真实路由空间。这对应源端的内联展开态，且避免将全量任务矩阵和“检测全部通路”绑定到
页面激活。`TaskRouteView` 已补充任务键、提示、子组、回退条目与温度语义；当前 mock 只是
受控展示数据，所有修改都有“尚未写入引擎”的明确提示。

对应回归：

- `src/lib/model-routing-session.test.ts`：默认继承、能力归一化、排序、批量覆盖、温度保留、模型替换与删除后的默认回退。
- `tests/settings-connectivity.spec.ts`：路由分组、温度编辑、备用排序、子流程批量应用、默认模型、含备用链的全组应用，以及折叠/打开后的单一会话恢复。
- `tests/primary-surfaces.visual.spec.ts`：1440×900 的 `settings_section=model-routing` 固定快照。

## 本轮补齐：声腔审听状态机

源端 `voice_studio/page.py` 的关键边界如下：

```text
编辑指导 ──保存──> 待审指导 ──生成试听──> 候选试听（未接受）
     │                    │                       ├─ 舍弃 ──> 待审指导 / 正式片段
     └─ 修改指导会舍弃旧候选 ┘                       └─ 接受 ──> 已接受、待后处理装配

脚本编辑 ──保存──> 旧音频、指导与候选全部失效
```

React 的 `voice-room-session.ts` 将该图实现为纯 reducer；`VoiceStudioPage` 仅持有
当前窗口期的草稿和候选状态。这样未来的 `EngineClient` 可把定时演示替换成真实的
take-draft / synthesize / accept / discard 命令，而不重写 UI 状态或改变确认顺序。

对应回归：

- `src/lib/voice-room-session.test.ts`：指导修改使候选失效、候选前不可接受、舍弃回退。
- `tests/voice-studio.spec.ts`：编辑、取消、生成、舍弃、接受、脚本修改清空旧状态。

## 下一轮实施顺序

1. **短篇同状态原生对照（P0）**：为已实现的短篇空白、已填、导入、校验失败、启动意向和
   要素偏好展开态补 PySide6/Tauri 同 viewport capture；保持 React 默认折叠，只有在展开
   对照态才比较 92 项库，避免把性能策略误判成视觉缺失。
2. **任务命令契约（P0，后端准备后）**：版本化 `EngineClient` commands，先接声腔 take
   draft、试听、接受与取消，再接短篇启动；所有命令返回 job id 与可订阅流，禁止 UI
   直接写 JSON 或调用 Provider。
3. **其余页面的行为状态基线（P1）**：为火候检测、章台导出/审计和卷帙终稿保存补同状态
   PySide/Tauri captures；模型路由下一步只补 Engine 读/写适配和真实 profile 状态，优先测试
   取消、关闭、未保存离开与失败。
4. **双 UI 长期维护**：任何 PySide 行为变更先更新本表、命名 fixture 和 reducer 测试，
   再更新 React；视觉截图只在同状态、同 viewport、同主题条件下比较。
