# 商业有声书声腔与音频交付架构

本文定义 Novel Forge 从定稿正文到可交付有声书的生产边界。目标不是让一次 TTS 调用“听起来像成片”，而是建立可复核、可局部返工、可追溯授权、可重新母带的生产系统。

## 1. 生产流水线

```mermaid
flowchart LR
    A[定稿正文与源哈希] --> B[参考配音脚本风格画像]
    B --> C[配音脚本生成与等义口语改写]
    C --> D[说话人裁决与配音导演审校]
    D --> E[平台能力投影]
    E --> F[MiniMax / 阿里百炼分段合成]
    F --> G[ASR 转写与已知文本对齐]
    G --> H{人声质量门}
    H -->|有局部证据| F
    H -->|通过| I[声音 cue 解析]
    I --> J[项目库 / 应用库匹配]
    J --> K[缺失素材生成]
    K --> L{试听与商用权利复核}
    L -->|通过| M[可审计 MixPlan]
    M --> N[voice / bed / sfx 独立总线]
    N --> O[24-bit premaster + 两遍响度母带]
    O --> P{商业交付总门}
    P -->|通过| Q[Master + SRT + 元数据 + 分轨包]
```

每个阶段只消费前一阶段的受控投影。平台、模型、声音角色、脚本版本与声音资产解析结果在执行计划中冻结；运行期间改变全局设置不会让同一章中途换平台或换模型。

## 2. 改写与风格模仿边界

### 2.1 两条文本轨

- `text` 是定稿正文，承担字幕、源哈希、审计与重新合成的事实基准，配音流水线不得修改。
- `spoken_text` 只允许等义口语适配，例如数字读法、停顿、可朗读断句和极少量冗余清理。专有名词、否定、数量、时间、因果和叙事事实必须保持。
- 改写结果同时经过长度比例、相似度、锚点与 LLM 专业审校；失败时回退到 `text`，不保留未经验证的改写。

### 2.2 参考配音脚本

新 Nimo UI 支持上传 TXT、Markdown、SRT 和 VTT。上传内容只在当前分析请求中存在；持久化的是抽象的 `DubbingStyleProfile`，不保存原文、连续台词或可反推出参考作品的长片段。

风格画像只学习可迁移维度：旁白密度、对白占比、平均句长、停顿密度、导演提示密度、情绪变化、环境声/BGM 使用倾向、叙述距离和句式节奏。提示词把参考文本视为不可信数据，忽略其中的命令；后续改写被明确要求“模仿方法而非复制措辞”。用户可调强度，但它不能覆盖文本保真、说话人安全门或平台能力合同。

## 3. 配音指导模型

导演指导采用“意图优先、声纹稳定、参数克制”的层次：

1. 先确定说话人、叙事功能、潜台词和对听众采取的行动。
2. 再确定交付方式：情绪、能量、紧张度、亲密度、叙述距离、吐字、气息、重音词与前后句连续性。
3. 最后投影到平台原生能力；不支持的控制不得伪装成已执行。

角色的长期声音身份与单场情绪分离。音色、年龄感、声线质地和叙述距离属于角色/旁白画像；愤怒、迟疑、压低声音等属于片段指导。极短句和身份锁定片段会降低自动数值补偿，避免声纹漂移。

## 4. MiniMax 与阿里百炼能力边界

| 维度 | MiniMax | 阿里百炼 / DashScope |
|---|---|---|
| 正式人声 | `speech-2.8-hd` 优先，Turbo 用于快速生成 | Qwen Audio 3.0 Plus 默认；可选 Qwen3/CosyVoice |
| 表演控制 | 原生 emotion、官方语气词、停顿、语言增强；不发送自由文本 instruction | Qwen Audio/CosyVoice/Qwen3 按模型投影自然语言 instruction 与受支持标签 |
| 长文本 | Speech 2.8 可开启 `continuous_sound`；分段仍保留源锚点 | 按具体模型字符限制分段，指令预算按模型分别裁剪 |
| 字幕/校音 | 请求原生 word subtitle，并以本地 ASR/对齐复核 | 统一使用 ASR 与已知文本强制对齐生成时间线 |
| 输出策略 | 人声单声道、CBR、多段稳定拼接；立体声在后期完成 | 人声与模型绑定；正式、试听、复刻、设计模型分开保存 |
| 音色安全 | 克隆必须记录说话人授权 | 克隆必须授权；Qwen/CosyVoice 音色 ID 与目标模型严格绑定 |

MiniMax 官方接口说明了 Speech 2.8、`<#x#>` 停顿、段落换行、长文本连续合成与字级字幕等能力：[MiniMax Speech T2A](https://platform.minimax.io/docs/api-reference/speech-t2a-http)。百炼模型、非流式 TTS、声音复刻与声音设计必须按账号地域、模型版本和官方限制配置：[百炼 TTS 模型](https://help.aliyun.com/en/model-studio/tts-model)、[非实时 TTS](https://help.aliyun.com/zh/model-studio/non-realtime-tts-user-guide)、[声音复刻与设计 API](https://help.aliyun.com/zh/model-studio/voice-clone-design-http-api)。

设置的唯一运行时来源仍是后端 `Settings`。Nimo 与 PySide 只编辑同一组受控参数；Nimo 是主要产品界面。新 UI 在切换平台时同时切换兼容模型，百炼的“当前平台模型”和“正式人声模型”保持同值，避免显示选择与真实合成模型分叉。凭据留空表示保留后端已有密钥，界面不回显秘密。

## 5. 环境声、SFX 与 BGM

声音设计输出的是锚定到脚本片段的 cue，而不是一段不可解释的总提示词：

- soundscape：持续的空间底色，例如雨、风、室内底噪；必须克制并为对白让位。
- SFX：一次性、可定位的事件，例如敲门、碎裂、来电；通过真实人声时间线解析到绝对位置。
- BGM：承担场景或人物动机，默认纯器乐；同名主题可复现，不同叙事功能不得因标签相近而误用同一首。

解析顺序固定为项目资产库、应用共享库、缺失后生成。AI 生成只创建候选，不自动等同于可发行资产。`approved` 表示听感可用；`commercial_use_status=cleared` 才表示已经记录商业权利依据。商业/Master 交付会阻止任何 `review_required` 或 `restricted` 的已解析声音资产。发布到应用库也同时要求听感批准与商用权利确认。

## 6. 混音、母带与交付包

ASR/强制对齐通过后，语义 cue 才转换为真实时间。MixPlan 保持 voice、BGM、soundscape、SFX 事件独立；BGM 与 soundscape 汇入 bed 总线，一次性 SFX 保持独立。人声重叠时采用侧链 ducking 与头部空间保护，避免用静态音量覆盖对白。

标准和商业档先渲染 24-bit PCM premaster，再以第一次响度分析结果执行第二遍 loudness normalization，最终有损格式只编码一次。商业档额外导出与同一 premaster 同源的 `voice`、`bed`、`sfx` WAV 分轨；有声书包包含 Master、章节字幕、质量/授权元数据与分轨，便于出版社重新平衡或制作平台特供版本。

## 7. 商业质量门

| 门 | 阻止条件 | 安全回退 |
|---|---|---|
| 正文与说话人 | 源哈希漂移、未知/歧义说话人 | 回退原文或进入人工复核 |
| 人声可懂度 | 转写错误率、覆盖率、时序异常 | 只返工有证据的片段，旧 take 保留 |
| 对齐基础设施 | 所有正式对齐器都降级/不可用 | 商业档阻止；试听档可带警告继续 |
| 声音完整性 | cue 未解析、资产缺失或文件损坏 | 保留 MixPlan 与缺失报告，不输出正式成片 |
| 商业权利 | BGM/环境声/SFX 未确认或受限 | 阻止商业/Master 交付与应用库发布 |
| 混音/母带 | 削波、响度、峰值、跨章一致性或混音风险不合格 | 保留 premaster/报告，禁止标记 delivery-ready |

“应用商业基线”只打开技术控制：master 能力计划、commercial 交付档、硬质量门、双对齐器、局部修复、字词级字幕，并关闭声音生成自动批准。它不能代替实际试听、授权文件或编辑签字。

## 8. 开源参考与许可证策略

开源项目用于学习能力拆分和处理链，不等于可直接打包进商业桌面应用：

- [AudioCraft](https://github.com/facebookresearch/audiocraft) 的 MusicGen/AudioGen 展示了音乐与环境音模型分离、条件生成和离线评估方式；其公开模型权重包含非商业许可，因此只作架构参考，不作为默认商业生成后端。
- [Spotify Pedalboard](https://github.com/spotify/pedalboard) 展示了专业效果链和流式处理接口；仓库采用 GPLv3，当前实现不直接嵌入，避免无意改变应用分发义务。
- [Stable Audio Open](https://github.com/Stability-AI/stable-audio-tools) 作为受管本地候选；安装前要求用户查看并接受对应代码、模型和基础模型条款，生成资产仍需逐项记录权利依据。
- FFmpeg 用于可审计 filtergraph、侧链、响度分析和编码。发布桌面包前必须核对实际构建选项及 LGPL/GPL 依赖组合。

任何新声音 Provider 必须在模型目录登记能力、版本、许可提示和默认商业状态，并通过统一资产服务写入来源、模型、提示摘要、请求哈希与审核记录；不得绕过资源库直接把生成文件塞入正式混音。

## 9. 发布前清单

1. 在 Nimo「平台设置」选择 MiniMax 或百炼，确认正式/试听/复刻/设计模型没有跨平台漂移。
2. 应用商业基线并保存；完成 sidecar 自检，确认至少一个正式 ASR/对齐路径可用。
3. 上传参考配音脚本时只确认抽象风格画像，不把参考作品台词复制进新脚本。
4. 完成角色音色、说话人、整章导演审校和局部重合成。
5. 在声音资源库逐项完成试听批准和商业权利复核，保留订单、条款版本或来源链接。
6. 检查质量报告、跨章一致性、Master、SRT 和 voice/bed/sfx 分轨，再导出有声书包。
