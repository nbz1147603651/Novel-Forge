# 创作指导、表达记忆与后续规划

本专题描述现有指导语义及规划发布机制；完整流程与入口差异见[小说模块现状](novel-workflow-current.md)，尚待实施的统一授权、工作台与前后端协作规则见[作者主导的 AI 协作方案](novel-authoring-control-design.md)。最后核对：2026-08-28。调整相关行为时同步更新这些文档与 AGENTS 索引。

## 指导语义

`core/guidance.py` 为现有章节契约增加来源 `source`、作用范围 `scope`、满足方式 `satisfaction` 和兑现状态。它是权威字段的投影，不建立第二套正史。

| satisfaction | 如何验收 |
| --- | --- |
| invariant | 涉及时不能违反事实；没有提及不构成违约，不要求复述数字或规则。 |
| narrative | 由行动、选择和后果兑现，不要求复述指导原话。 |
| literal | 仅明确列入 `required_literals` 的原文需要保留，指定 `scene_id`。 |
| optional | 可以省略或替换；缺席不扣分、不触发补写。 |

来源投影中的世界规则是事实边界；章节明确的事件、推进职责是叙事义务。全书主题仍作为背景保留，不再自动加入每章 `theme_duties`。规划不能把引号或数字自动转为字面义务。

`CrossSceneRef.requirement` 默认 optional，包括没有该字段的旧引用。只有明确声明的 narrative/literal 引用进入 WAVE 覆盖诊断及 Review 路由；可选引用不计入分母、不产生修复票据。必需结果、因果、POV、密码原文等原有检查继续运行。局部关键词匹配仍只是覆盖诊断，不能代替模型对因果意义的判断。

Planning、整章/分场景写作、WAVE、主要审校修复、短篇和拟人化步骤通过 PromptBuilder 消费统一语义。字面覆盖报告随正文重算，包含文本哈希和兑现证据；事实/因果的语义验收仍由现有审校完成，不能由字面出现次数代替。

## 表达记忆

- 出现次数、沉寂时长和模型给出的 `is_intentional` 不再自动生成加强任务或豁免密集重复。
- 同步建议只选择本章目标、事件、进展或 `motif_requests` 明确涉及的意象；异步前瞻还可根据本章目标进行语义相关检索。相关仅表示可参考，不代表必须使用。
- `MotifOccurrence` 保存 `narrative_function`、`function_relation`（new_function/redundant/unknown）和 `function_evidence`。抽取器比较近期表达功能，换同义词仍可能重复同一作用。
- new_function 必须有当前正文证据才可豁免频次告警；无法证明时保留告警，交给审校判断。显式用户保护可用 `metadata.repetition_source=user_explicit`，普通模型意图标签不能获得同样权限。
- 事实、承诺和表达沿用既有独立存储与最终正文回写通道；本次不迁移或改写历史小说数据。

## 后续大纲策略

### 全书目标与初始化规划范围

新项目默认 `planning_commitment=full`，按目标总章数分批生成大纲和契约。显式选择 `progressive` 时，首次只规划前 10 章（其中前 5 章细化并同步契约），但这不是全书章数上限；后续随章节执行推进。已有草稿或初始化请求中显式保存的策略保持不变。

卷帙 → 章节大纲显示全书目标、已有大纲数量和细化范围。已有渐进项目可以选择「补齐全书规划」，保留总章数、已确认章节和正文，不必用「延长全书」增加目标章数。该操作会产生模型调用和用量；确认后在独立候选目录补齐、严格同步契约与来源投影，通过检查才整体发布。失败保留原规划，候选文件留存供审计；进入未细化的下一章时也会重新尝试推进。

接口沿用 `extend_outline`：`target_total` 等于当前总章数表示补齐（必须同步契约，不停用原结局），大于当前总章数或使用 `additional_chapters` 才表示延长。完整规划再次补齐是无操作。下面的 `future_planning_mode` 控制的是对后续剧情的探索与修订，和是否补齐规划是两个独立选项。

全局设置：

```dotenv
NOVEL_FORGE_FUTURE_PLANNING_MODE=fixed
NOVEL_FORGE_FUTURE_PLANNING_WINDOW=4
NOVEL_FORGE_FUTURE_PLANNING_BUDGET_RESERVE_USD=1.0
```

`fixed` 默认不探索；`proposal` 保存候选供审阅；`adaptive` 允许通过检查后自动发布。项目可在 `plans/planning_policy.json` 覆盖策略并指定人工锁定章节，例如：

```json
{"mode": "proposal", "locked_chapters": [8, 16]}
```

直接 `execute_run_chapter` 入口在章节 completed 并完成必需状态处理后检查幕、卷、蓝图转折点或本章重规划事件。prepare/resolve 检查点及引擎连跑目前没有同等的归档后 future-planning 回调；不能因为共享 workspace 就推断所有入口已经一致。渐进细化在下一章 prepare 时有兜底补足，但它不同于未来剧情探索，也不是已实现的独立后台预规划任务。

未来剧情探索最多生成一个后续窗口候选，原方案始终保留。候选生成、契约同步、独立审查分别受预算余量检查保护；网关继续执行实际日/月总预算。余量是保守估计，不是单次调用价格保证。该步骤失败不使已经接受的章节失败。统一归档触发、批准版本和重大变更门禁是协作方案中的待实施要求，不能把模型评审直接等同于作者批准。

候选使用已接受的完整正史（包括归档事实）、出口状态、承诺及用户意图作为边界。上下文或预算不足时保留旧规划，不静默截断历史事实。独立 `REVIEW_FUTURE_OUTLINE` 比较事实、用户意图、人物动机、因果、承诺、同步契约和创作收益；全部通过且置信度达到门槛才能发布。模型评审不是文学质量保证。

章号、总章数、全局结构、已成稿章节和人工锁定章节不能自动改动。候选越界或同步触及受保护契约时保留旧规划并记录原因；涉及这些边界的调整须另行确认。proposal 模式不自动切换有效版本，当前没有新增 UI 审批按钮。

## 发布、回退与恢复

候选位于项目 `.planning_revisions/<revision_id>/candidate/<project_id>/`，保存原始输入快照和评估结果。现有大纲润色入口也使用相同隔离同步机制。

1. 在候选目录同步章节契约、来源投影、里程碑和过期标记；严格同步不接受缺失章节或本地回填作为成功。
2. 发布前再次检查输入是否变化；自适应还核对完整正史和成稿章节集合。持续更新的工作流进度清单不作为规划输入，也不由候选覆盖。
3. 持有项目独占锁，先写 `planning_publish.json` 回退日志，再写入全部变更并失效未来 JSON 缓存。
4. 写盘失败恢复每个文件的旧内容；进程中断后，下次独占工作区操作恢复。共享读取和章节 preflight 拒绝使用未完成的发布，防止消费半更新版本。

发布后停用初始化时生成的旧大纲语义提示（含预取缓存），改以当前章节来源投影与契约为准；已经发生的事件、关系和承诺记忆继续保留。本次不自动重建旧大纲向量索引。

这是一组文件在项目锁下的逻辑事务；它不让绕过项目锁直接读文件的外部程序获得数据库式快照隔离。旧正文、正史数据库和记忆不在发布写入范围。候选保留供审计，不自动清理。

## 验证与后续评测

自动回归覆盖实际中文/英文/兼容模板渲染、密集重复、可选引用缺席、数字事实与密码原文区别、功能变化证据、规划边界、预算跳过、同步失败、并发输入变化和中断恢复。

真实模型对照评测需另行授权固定预算。建议使用连续章节与较长记忆窗口，记录无新增作用的复述、事实/因果错误、人物声音、自然度、误报和调用成本；不能仅凭单章分数宣布改进。
