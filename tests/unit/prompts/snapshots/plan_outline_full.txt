### 6. 支线规划 (subplot_plan)
- **概念边界：支线是"独立叙事线"，有自己的人物、事件、起承转合、收束**
  - 支线区别于角色弧光：支线有外部事件进程，角色弧光是内在心理变化
  - 支线区别于主线：支线服务于主线主题或角色，但有独立的故事弧
- **复杂度引导**（按叙事复杂度推荐支线数量）：
  根据叙事复杂度（标准），建议规划 **2-4 条支线**。
  - **支线来源推导**：
  根据本作品的体裁(mystery)、核心冲突(The archive proves one ally has hidden evidence.)、
  角色阵容、世界规则与已选叙事要素，自主推导 2-6 条支线。推导方向只作为功能轴参考，不是题材模板：
  - 情感/关系线（角色间的张力与变化）
  - 谜团/探索线（信息不对称与揭示节奏）
  - 势力/博弈线（派系冲突与权力动态）
  - 成长/能力线（角色内在或外在能力的进阶）
  - 世界观/规则线（设定揭示与验证）
 - **密度约束**：每条支线至少 3-5 个 chapter_events（确保支线有足够叙事容量）
 - **交织结构约束**（每条支线必须同时满足以下 3 项）：
   ① 至少 1 条【主线→支线】link（link_type 必须为 trigger_start 或 trigger_turn）
   ② 至少 1 条【支线→主线】link（link_type 必须为 feed_main 或 reveal_key）
   ③ theme_echo / create_tension / constrain 为加分项，**不计入**上述最低要求
  - 每条支线给出 involved_chapters（章节编号列表），避免后续大纲无法落地
  - **交叉约束**：`weave_links` 中每个 `trigger_chapter` 必须包含在 `involved_chapters` 中。若支线在某章反哺主线，该章必须同时出现在 `involved_chapters` 和对应 weave_link 的 `trigger_chapter`
  - 每条支线必须给出 chapter_events（逐章节节点事件），每个节点绑定 chapter_number 与 event，章节号需与 involved_chapters 对齐

#### 支线交织关系（核心原则：环环相扣、最终收敛、服务于主线）
 - **全局交织密度**：
   - 全书层面：支线→主线的反哺关系（feed_main/reveal_key）总数 ≥ 支线数量
   - 时间分布：交织触发章节应分散在不同叙事阶段，避免集中在单一阶段
   - 主线转折关联：至少半数已规划关键转折应有支线 weave_link 指向
 - **每条支线必须与主线形成闭环**：
   - 主线触发支线启动（至少一个 link_type='trigger_start'，禁止仅用 trigger_turn 替代）
   - 支线反哺主线推进（至少一个 link_type='feed_main' 或 'reveal_key'，**禁止使用 theme_echo 替代**）
 - **支线间可形成因果链**：A 的结果触发 B 的启动，但最终都需收敛到主线
 - **交织关系类型**（link_type）：
   - 【主线→支线】trigger_start（触发启动）/ trigger_turn（触发转折）/ constrain（约束走向）/ enable（提供条件）/ conflict（制造冲突）
   - 【支线→主线】feed_main（反哺主线转折）/ reveal_key（揭露关键信息）/ create_tension（制造主线张力）/ theme_echo（呼应主题升华）
 - **收束路径规划**（每条支线必须明确）：
   - resolution_chapter: 在哪一章收束
   - resolution_target: 收束到哪里（**primary/normal 优先级必须为** 'main_turning_point:N' 或 'character_fate:角色名'；仅 background 优先级允许 'theme_echo'）
   - resolution_type: 如何收束（'resolve'问题解决 / 'reveal'悬念揭示 / 'ascend'价值升华 / 'merge'并入主线）
 - 对于 chapter_events 中的关键节点，若涉及与其他线索的互动，填入 weave_notes 说明
 - 若某节点依赖前序支线结果，`depends_on` 必须填写为数组；单个依赖也写成 ["支线名:章节号"]，没有依赖写 []，禁止写成字符串
 - `weave_links` 必须是对象数组；数组元素只能是 `{...}` 对象，禁止插入空字符串 `""`，禁止把 `"source_type": ...` 这类字段直接摊平在数组里
 - 为每条支线标注 priority（primary/normal/background）

### 8. 悬念时间表 (suspense_schedule)

为全书规划核心悬念节点，确保悬念铺设与兑现节奏可控：

#### 悬念类型（必须从以下5种中选择）：
- **mystery（谜团）**：读者与角色尚未获得的关键信息、真相或规则缺口。
- **crisis（危机）**：迫近的外部威胁、损失风险或局势失控点。
- **emotion（情感）**：关系变化、情绪冲击、信任裂缝或亲密张力。
- **choice（抉择）**：会改变代价、阵营、关系或主线方向的选择。
- **desire（渴望）**：角色强烈追求被阻断、延迟或重新定义。

#### 悬念紧迫度（决定悬念持续张力）：
- **critical（临界）**：悬念必须在当前章节立即解决
- **high（高）**：悬念应在2-3章内兑现
- **normal（正常）**：悬念可跨越5-10章后兑现
- **low（低）**：悬念可作为全书伏笔，长线铺垫

#### 规划要求：
 - 每条悬念必须关联 **related_subplot**（支线名称），形成悬念-支线绑定
 - `related_subplot` 只能写 `"主线"` 或已经存在的支线名称完整原文；禁止临时发明任何未在支线规划中建档的名字
 - 若悬念属于角色弧光、主线反转或人物抉择，但没有对应独立支线，则 related_subplot="主线"
 - 若确实需要独立支线，必须先在支线规划中建立同名支线，再在 `suspense_schedule` 精确引用该名称
 - 每条悬念需规划 introduce_chapter（引入章节）与 resolve_chapter（计划兑现章节）
 - 悬念总数建议 3-8 条，覆盖全书关键节点
 - **strand_affinity**（追读力系统必需）：每条悬念需标注与三条情节线的关联度
   - quest（主线推进）/ fire（情感爆发）/ constellation（伏笔编织）
   - 值为 0-1 的浮点数，总和约等于 1.0；根据该悬念实际推动的功能估算，不要机械平均。

- `subplot_plan` 写支线计划，每条支线包含名称、描述、涉及章节、章节事件、交织链接、优先级、收束章节、收束目标和收束类型。
- `suspense_schedule` 写 3-8 条核心悬念，每条包含稳定 ID、类型、引入章节、兑现章节、描述、紧迫度、关联支线和 `strand_affinity`；`related_subplot` 只能写 `"主线"` 或 `subplot_plan[].name` 的完整原文。
- `ending_strategy` 说明主线、人物弧光、主题承诺和关键悬念如何在结尾落地。
- `chapter_rhythm_curve` 写 1..24 每章的节奏目标，每项包含 chapter_number、target_pacing(1-5)、target_tension(1-5)、beat_pattern(字符串)、description。

## 重要约束
1. 确保各部分相互协调，形成统一的故事愿景
2. 主线、支线、人物弧、悬念和结局必须互相校准，支线不得像独立轨道后贴上去。
3. narrative_phases 的章节区间必须覆盖 1..24，且区间不重叠、不断档
4. key_turning_points 与 character_arcs 的 milestones 必须落在有效章节编号内
5. 保持与故事规格的一致性，禁止脱离体裁/基调/语言要求
6. 蓝图必须可操作，能直接指导后续分批章节大纲生成
7. `subplot_plan[].chapter_events` 中每个 `chapter_number` 必须属于对应 `involved_chapters`
8. **支线密度约束**：`subplot_plan` 中每条支线的 `chapter_events` 数量 ≥ 3
9. **支线交织结构约束**：
   a. 每条支线 `weave_links` ≥ 2
   b. 其中至少 1 条 `link_type` 为 `trigger_start` 或 `trigger_turn`（主线触发支线）
   c. 其中至少 1 条 `link_type` 为 `feed_main` 或 `reveal_key`（支线反哺主线）
   d. 禁止所有 `weave_links` 都是 `theme_echo`/`create_tension`/`constrain`
10. **悬念 strand_affinity**：`suspense_schedule` 中每条悬念必须包含 `strand_affinity` 字段，key 为 quest/fire/constellation，值为 0-1 浮点数
11. `subplot_plan[].chapter_events[].depends_on` 必须始终是 JSON 数组；单个依赖写成 ["支线名:章节号"]，没有依赖写 []
12. `character_arcs[].milestones[]` 每个对象只允许 `chapter_start`、`chapter_end`、`description` 三个英文 `snake_case` 字段；补充说明必须写进 description
13. `suspense_schedule[].related_subplot` 必须精确匹配 `"主线"` 或某条 `subplot_plan[].name`；如果是角色弧光节点且没有独立支线，写 `"主线"`，不要新造支线名
14. `chapter_rhythm_curve` 必须覆盖 1..24，target_pacing 与 target_tension 必须是 1-5 整数，beat_pattern 必须是字符串。
